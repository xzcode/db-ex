# SQLite and preferences continuation (development branch)
- Local SQLite file creation (exclusive, no overwrite), opening, saved profiles, database/table/view explorer, parameterized filters, SQL editor, metadata/DDL, bounded CSV/JSON import/export, confirmed writes, primary-key/old-row optimistic updates and deletes, transactions and native online file backup.
- SQLite uses Electron's embedded Node SQLite module in a dedicated, terminable utility process (a Node child process for standalone tests); no new native dependency, no SQLite server or CLI required. SQLite starts with a read-only handle; only confirmed writes open a writable handle. Read queries remain query-only. File attachment, extension loading, arbitrary PRAGMA, multi-statement scripts and VACUUM are not available through the editor. BLOB/unsafe-integer rows cannot be losslessly edited or exported using the generic grid; use online database backup for those values. SQLite index names are shown in field metadata.
- Shared relational IPC retains the historical mysql.* operation names but dispatches according to actual session type. SQLite does not accept MySQL database creation/deletion operations.
- Separate SQLite page size and storage-class color palette, query drafts, current/last workspace connection tabs, selected database objects and editor views; restoration does not restore write access or auto-execute user queries. Mongo text-filter drafts and Redis command drafts are saved independently. Encrypted record-edit drafts restore only on explicit request after enabling writes; the original record is retained for conflict checks. Drafts are bounded by the existing 100,000-character limit. In-memory query text is retained per object during selection changes. Periodic persistence does not guarantee the last unsaved keystroke on forced exit.
- SQL completion uses already-loaded table/field metadata, keywords and common functions; Mongo aggregation and Redis console provide engine vocabulary. This is not a full parser or server-wide schema index.
- Native tool version checks execute the explicitly confirmed executable with a fixed --version argument. Direct MySQL connections support mysqldump backup and mysql SQL restore; direct MongoDB connections support archive dump/restore and collection JSON import/export. Credentials are written only into private temporary option files, removed on normal completion; do not use a tool executable from an untrusted source. SSH, proxy, TLS, multi-node and Mongo URI tool workflows are not supported yet. Restore uses explicit write permission and native confirmation; SQL restore executes a user-selected script, which may affect other databases if the script says so. Mongo restore does not drop collections by default. Failed operations can have partially applied writes. Shell launch with mongosh/redis-cli/sqlite3 is not included (version checks only).
- M6 local verification: 114 tests passed, 8 environment-dependent tests skipped, no failures; typecheck and build passed. Native MySQL 8.4 and MongoDB 8 authenticated backup/restore and EJSON import/export passed against dedicated Docker fixtures; no existing user databases were used. SQLite child-process termination during a long native query rolled back an uncommitted transaction. Browser UI verification on the Seoul server was blocked by missing system libraries (libgbm.so.1 and libasound.so.2). No full native platform/release claim until CI and packaging finish. New UI settings have localized labels; newer diagnostic keys use English fallback outside simplified/traditional Chinese.
