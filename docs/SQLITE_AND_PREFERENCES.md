# SQLite and preferences continuation (development branch)
- Local SQLite file creation (exclusive, no overwrite), opening, saved profiles, database/table/view explorer, parameterized filters, SQL editor, metadata/DDL, bounded CSV/JSON import/export, confirmed writes, primary-key/old-row optimistic updates and deletes, transactions and native online file backup.
- SQLite uses Electron's embedded Node SQLite module in a dedicated worker; no new native dependency, no SQLite server or CLI required. SQLite starts with a read-only handle; only confirmed writes open a writable handle. Read queries remain query-only. File attachment, extension loading, arbitrary PRAGMA, multi-statement scripts and VACUUM are not available through the editor. BLOB/unsafe-integer rows cannot be losslessly edited using the generic grid.
- Shared relational IPC retains the historical mysql.* operation names but dispatches according to actual session type. SQLite does not accept MySQL database creation/deletion operations.
- Separate SQLite page size and storage-class color palette, query drafts, current/last workspace connection tabs; restoration does not restore write access or auto-execute user queries. Mongo text-filter drafts and Redis command drafts are saved independently. Unsaved row edits and exact object/tab editor positions are not restored yet.
- SQL completion uses already-loaded table/field metadata, keywords and common functions; Mongo aggregation and Redis console provide engine vocabulary. This is not a full parser or server-wide schema index.
- Native tool version checks execute the explicitly confirmed executable with a fixed --version argument. Direct MySQL connections support mysqldump backup and mysql SQL restore; direct MongoDB connections support archive dump/restore and collection JSON import/export. Credentials are written only into private temporary option files, removed on normal completion; do not use a tool executable from an untrusted source. SSH, proxy, TLS, multi-node and Mongo URI tool workflows are not supported yet. Restore uses explicit write permission and native confirmation; SQL restore executes a user-selected script, which may affect other databases if the script says so. Mongo restore does not drop collections by default. Failed operations can have partially applied writes. Shell launch with mongosh/redis-cli/sqlite3 is not included (version checks only).
- No full native platform/release claim until CI and packaging finish. New UI settings have localized labels; newer diagnostic keys use English fallback outside simplified/traditional Chinese.
