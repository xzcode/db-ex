# DB EX Internationalization

## Supported locales

- `zh-CN` — 简体中文.
- `zh-TW` — 繁體中文.
- `en` — English.
- `ja` — 日本語.
- `ko` — 한국어.
- `de` — Deutsch.
- `fr` — Français.
- `es` — Español.
- `pt-BR` — Português.
- `ru` — Русский.
- `it` — Italiano.
- `ar` — العربية (right-to-left).
- `hi` — हिन्दी.
- `id` — Bahasa Indonesia.

`system` is the default on a fresh installation. The Electron main process queries the OS preferred languages; the renderer falls back to the browser locale if native IPC is unavailable. Regional tags use their matching language (e.g. es-MX → es, pt-PT → pt-BR, zh-HK → zh-TW). An unsupported system language falls back to English. Users may explicitly override the system setting.

All 14 locales cover the 325 core UI and native dialog strings. The eleven additional non-Chinese/English catalogs include 408 translated entries each, including frequent diagnostics and operation notices; remaining cataloged diagnostics use English as fallback. Traditional Chinese has a complete 691-key catalog. Uncataloged driver messages are preserved verbatim. Arabic uses right-to-left layout; code and database results retain left-to-right presentation.

The toolbar selector switches the renderer reactively without restarting or disconnecting sessions. The local preference is stored under `dbex.language`; the resolved locale is synced over the explicit preload IPC bridge for application-owned native dialogs. Platform-provided dialogs and third-party editor chrome may follow their own system locale.

## Adding a language

1. Create a JSON catalog in `src/shared/i18n/`, following `catalog-ja.json`. Stable source keys are Chinese UI strings; each translation must retain the same numbered placeholders, such as `{0}`.
2. Register the locale in the shared `languages` table, catalog map and system locale resolver. The toolbar, types, main-process validation and direction are derived from the same table.
3. Translate static Vue labels, tooltips, placeholders and accessibility labels with `t(key, values)`. Translate application-generated notices and errors with `localizeMessage`. Use `translate(locale, key, values)` for native confirmation and file dialog text. Do not translate any user-controlled query, host, saved connection name, database identifier or result cell.
4. Keep error codes, Mongo/Redis/MySQL command names, credential handling, and write-confirmation semantics stable across all languages. Never remove original diagnostic information if a message is not yet cataloged.
5. Add language-specific unit and browser UI checks; run typecheck, tests and the packaged application verification.

The locale framework is dependency-free except for Vue's existing reactivity. Language catalogs are bundled, work offline, and do not call any translation service.
