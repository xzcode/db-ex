# DB EX Internationalization

## Supported locales

- `zh-CN` — Simplified Chinese (source message catalog).
- `en` — English.
- `system` — Chinese system locales resolve to Simplified Chinese; all other languages use English until their own resources are added.

The toolbar selector switches the renderer reactively without restarting or disconnecting sessions. The local preference is stored under `dbex.language`; the resolved locale is synced over the explicit preload IPC bridge for application-owned native dialogs. Platform-provided dialogs and third-party editor chrome may follow their own system locale.

## Adding a language

1. Create a catalog in `src/shared/i18n/`, following `catalog-en.ts`. Stable source keys are Chinese UI strings; each translation must retain the same numbered placeholders, such as `{0}`.
2. Register the locale in `Locale`, `LanguagePreference`, `isLanguagePreference`, the catalog map and system locale resolver. Expose the option in App.vue; update the main-process allowlist.
3. Translate static Vue labels, tooltips, placeholders and accessibility labels with `t(key, values)`. Translate application-generated notices and errors with `localizeMessage`. Use `translate(locale, key, values)` for native confirmation and file dialog text. Do not translate any user-controlled query, host, saved connection name, database identifier or result cell.
4. Keep error codes, Mongo/Redis/MySQL command names, credential handling, and write-confirmation semantics stable across all languages. Never remove original diagnostic information if a message is not yet cataloged.
5. Add language-specific unit and browser UI checks; run typecheck, tests and the packaged application verification.

The locale framework is dependency-free except for Vue's existing reactivity. Language catalogs are bundled, work offline, and do not call any translation service.
