# Named query objects

## Scope
- MySQL, MariaDB and SQLite use SQL query objects. MongoDB has separate Query and Aggregation Pipeline folders. Redis continues to use its own command console.
- Database query folders use local saved-query metadata, not objects created in the database server. A saved connection ID, engine and database form the storage scope. Temporary connections can run a query but must be saved before persisting named queries.
- The Objects catalog shows name, actual UTF-8 content size, created date and updated date, with search and sortable columns. Local offline storage has no server-side created/modified user identity, so the interface does not invent those columns.
- Double-click opens a saved query in its own tab. Multiple new drafts are independent. Saving updates the existing ID and revision; Save As creates a new object. Catalog rename, copy, delete and import are separate operations. Ctrl/Cmd+S saves the active query; Shift+Ctrl/Cmd+S opens Save As. Initial unnamed save prompts for a name. Closing dirty tabs, a database, or a connection asks for confirmation.
- The independent encrypted saved-queries.secure.json store uses the existing application cipher and atomic serialized writes. Named queries are not subject to the history/favorites 100-entry cap, and are never evicted to make space for history. The existing 16 MiB encrypted-file limit remains. Name uniqueness is case-insensitive within each connection/database/query mode, and revision checks prevent stale overwrites.
- Previously saved history and favorites remain untouched in queries.secure.json. Existing favorite queries can be loaded explicitly into a new editor and saved into the new library; legacy unscoped queries are not automatically assigned to multiple server connections. SQL history now also retains bound parameter JSON.
- SQL objects preserve both statement and parameter text. MongoDB find objects preserve Filter/Projection/Sort EJSON and target collection; aggregation objects preserve pipeline text and target. Import and saving do not execute queries. Structured MongoDB operations still use the existing guarded driver, not a general JavaScript interpreter.
- Import accepts .sql text for relational engines or the versioned .dbex-query.json portable file of the matching engine/mode. Export to JSON preserves query text and parameters; raw SQL export omits parameters and warns first. Both portable formats are plaintext with confirmation; connection credentials and internal connection IDs are excluded. Imported copies receive unique names.
- Existing main-process native write confirmation, transaction rules and read-only defaults remain unchanged. Saved queries never auto-execute when opened or restored. Workspace restoration supports the most recently selected saved query; saved-object draft recovery is scoped by its persistent ID when auto-recovery is enabled. Multiple entirely new, unnamed draft tabs are not restored across app restarts.
- The query editor retains SQL syntax/metadata completion and MongoDB structured filter/pipeline editing. Full mongosh script execution, general Mongo shell method completion and SQL script formatting are not included in this query-storage batch.

## Verification
Targeted tests: independent encrypted persistence, 105 saved objects (above former cap), exact parameters, scope isolation, revisions, rename/copy/delete, versioned import/export, and workspace compatibility. Browser tests cover named SQL persistence and catalog actions, MongoDB query and pipeline catalogs, object tabs, and restoration. The packaged smoke script additionally exercises real SQLite saved-query IPC and encrypted file persistence. Final native platform checks still run in integrated CI.
